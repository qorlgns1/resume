## 남은 작업 메모

- 사용자 페이지 추가: `kind: "custom"`, `/p/[slug]` 같은 라우팅, 메뉴 편집, 어드민 페이지 추가·삭제
- 프로필 사진: 프로필 스키마에 이미지 필드가 아직 없습니다 (미디어 저장소는 준비됨).
- 드래그 편집: 지금의 숫자 입력(col/colSpan/row) 위에 덧붙입니다. 라이브러리는 실제 편집 경험을 보고 고릅니다.

## 알려진 제약

- 업로드 이미지는 ID를 알면 누구나 열 수 있습니다(초안에만 쓴 이미지 포함). ID는 추측하기 어려운 무작위 값입니다.
- 올리고 쓰지 않은 이미지는 자동으로 지우지 않습니다. 콘텐츠 › 미디어에서 직접 삭제합니다.
- 공개 사이트의 `/media`는 요청마다 어드민에서 가져옵니다. 응답에 1년 캐시 헤더가 붙으므로, 앞단에 CDN·리버스 프록시 캐시를 두면 어드민 부하가 줄어듭니다.
- 공개 페이지는 요청마다 렌더링합니다 (`connection()`). 게시 즉시 반영되지만 매 요청마다 어드민 API를 호출합니다. 방문자가 많아지면 게시 시 재검증하는 캐시를 붙입니다.
- 로그인 시도 제한은 메모리에 저장되므로 어드민 프로세스를 여러 개 띄우면 프로세스마다 따로 셉니다 (단일 서버 전제).
- 실행 중 백업 명령(`VACUUM INTO`)은 아직 없습니다. 지금은 어드민을 멈춘 뒤 `/data`를 복사합니다.
- 공개 API 응답의 `content`에는 전체 라이브러리가 들어 있습니다. 게시 구조를 정할 때 페이지가 참조하는 항목만 담도록 줄일 수 있습니다.
- 모바일 `custom` 순서는 CSS `order`를 쓰므로 스크린 리더의 읽기 순서와 다를 수 있습니다 (편집 화면에 안내 문구 표시).
- 프로젝트 목록 등 참조 선택은 체크한 순서대로 표시됩니다. 순서를 바꾸려면 체크를 풀고 다시 체크해야 합니다.
- 초안 저장 버튼이 꺼져 있을 때의 이유는 상태 배지와 버튼의 title로만 안내합니다.
- 어드민은 1100px 이상 데스크톱 화면을 기준으로 만들었습니다.
- 스모크 테스트는 31xx 포트를 사용합니다. 그 포트가 이미 쓰이고 있으면 실패합니다.
- Docker 이미지는 Node 24 alpine 기준이며, 크기는 약 300MB입니다 (최적화 전).
